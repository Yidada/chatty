# iOS Mika 对话体验 · 设计预览计划

日期：2026-09-12。状态：设计候选，待体验反馈。仅调用 sdlc-plan，不开启新的生命周期阶段。

## 问题与边界

- 用户需要接近 DeepSeek 的清爽界面和自然聊天体验，同时持续跟踪所有有权限查看的项目任务，包括其他人创建的工作。
- 已确认：保留 Mika、项目上下文、连续发送、头像设置、动态红点及任务验收。
- 当前代码：WorkspaceTabs 默认动态，三个 Tab；ChatScreen 输入区独立项目行与较多执行信息；ChatModel 已支持出站队列和会话恢复。
- 设计假设：以 Mika 为首页，两个主入口能降低操作负担。项目目录放在历史侧栏和项目选择面板仍需验证。
- 关键冲突：完全照搬单一聊天入口，会再次让项目任务进展难以找到。候选保留常驻动态入口。

## 本轮最小交付

当前会话中的交互式 iPhone 设计稿，使用合成数据，不连接服务、不上传附件、不发送真实消息、不构建或发布产品。

1. Mika 空白页：简洁标题、历史入口、头像、轻量建议、项目与附件统一输入区。
2. 长回答及连续发送：正文优先，过程可折叠，每条出站消息保存发送时的项目。
3. 对话历史：搜索、切换、新建、每个对话独立草稿。
4. 动态与验收：最近/待关注、他人任务、阅读与完成分离、查看结果、模拟确认成功或失败。
5. 项目目录与头像设置：项目概览入口、深浅外观切换。

不包含真实 AI、操作系统推送、跨设备未读同步、键盘与语音实机行为。浏览器里的定时响应仅用于演示。

## 可观察验收标准

| 场景 | 检查 |
| --- | --- |
| 启动 | 首屏可以直接输入；主入口仅 Mika/动态；头像可以进入设置 |
| 连续发送 | 第一条模拟处理期间，第二、第三条仍可提交，并各自保留项目标记 |
| 草稿 | 切换对话再返回，未发送文字仍在原对话 |
| 项目切换 | 已发消息项目不变，新发消息使用新选择 |
| 长回答 | 默认仅显示一行执行摘要，展开可查看过程；正文与输入区清晰可读 |
| 未读与待关注 | 打开周报结果后对应未读消除，周报仍在待关注 |
| 验收成功 | 点击确认后先显示处理中，模拟确认成功后才移出待关注 |
| 验收失败 | 模拟确认失败后保留待验收，显示可重试提示 |
| 团队任务 | 动态包含其他成员创建的任务，不以聊天发起人为过滤条件 |
| 外观 | 深浅模式均使用相应正文、次要文字与输入表面颜色 |
