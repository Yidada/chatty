## 本轮规划者判断（需在计划评审时确认）

| 编号 | 判断 | 理由 | 若被否决的后果 |
| --- | --- | --- | --- |
| J1 | **不做「深度思考 / 智能搜索」开关** | Multica 服务端没有对应请求参数，Mika 运行时自行决定思考与检索；做一个点了没用的开关比没有更糟，且会误导用户以为能改变行为 | 若坚持要开关，需要先推动服务端新增参数，属于跨服务改造，本 change 应降级为「等待依赖」 |
| J2 | 过程块的「已搜索到 N 个网页 / 已浏览 N 个页面」**不逐字照搬** | Multica 的 `TaskTrace` 是 `thinking / tool_use / text` 三类（`scripts/chat-fixture.py:40-51`），没有「网页数 / 页面数」字段 | 照搬会产生永远为空的文案；规范改为把 `tool_use.tool` + `content` 映射为可读步骤行 |
| J3 | 过程块**默认在生成中展开、结束后自动折叠**，而不是始终折叠 | 与 DeepSeek v2.5.1 release notes「支持思考过程自动折叠」一致；也给长回答留出正文主导的默认视图 | 始终折叠会让「正在思考」失去可观察性，削弱本轮最主要的价值 |
| J4 | **保留非聊天入口**（动态 + 项目），只重写 Mika 页 | Chatty 的产品价值包含全工作区事项跟踪；`docs/ios-mika-design-plan.md` 已识别「完全照搬单一聊天入口，会再次让项目任务进展难以找到」 | 若改为 DeepSeek 式单入口，动态/项目的可达性需要在规范里重做，属于扩大范围 |
| J5 | 用户消息用**淡蓝紫气泡**、Mika 回答**全宽无气泡**，并采用 DeepSeek 的品牌蓝紫强调色 | 一手截图 `ds/us3.png`、`ds/cn4.png`、`ds/cn5.png` 均为该形态；用户选择对齐视觉语言 | 保留绿色主题则「视觉设计语言」这一项未达成 |
| J6 | 草稿存储从 `account/workspace/agent` 改为 `account/workspace/agent/session`，并**保留旧记录的一次性迁移** | 现有 `ProtectedStorage.draft()` 一个 Agent 只有一份草稿，切会话会串内容；用户当前工作区可能已有未发送草稿，不能丢 | 不迁移会让升级用户丢失草稿；不改造则「每个会话独立草稿」不成立 |

## 规范定稿阶段的决策（2026-09-12，用户直接选择）

| 编号 | 决策 | 依据 | 影响 |
| --- | --- | --- | --- |
| U1→D5 | **保留「动态 / Mika / 项目」三 Tab**，本期只重写 Mika 页；入口收敛推迟 | 用户选择「保留三 Tab」 | `spec.md §3.1` 定稿为方案 B；导航零回归；这是本期唯一有意保留的信息架构差异（`spec.md §13.7`） |
