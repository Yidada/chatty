# DeepSeek 移动端（iOS / Android）UI/UX 逐屏调研报告

**调研日期**：2026-09-12（当天 App Store 版本 2.5.1，2026-09-12 发布）
**调研对象**：官方 App「DeepSeek - AI Assistant / DeepSeek - AI 智能助手」，App Store id 6737597349，开发者 杭州深度求索人工智能基础技术研究有限公司；Android 包名 `com.deepseek.chat`
**证据分级**：
- **(a) 已验证（有 URL）**——文字或截图直接来自可访问来源
- **(b) 从截图推断**——图片可见但无权威文字说明，属于我的视觉判读，可能有误差
- **(c) 未知**——查不到，明确写"未知"，不做猜测

> ⚠️ 重要前提：DeepSeek 在 **2026-09-10 前后做了一个破坏性改版**（合并 快速/专家/识图 三模式，即 v2.5.0/2.5.1）。网上大量 2025 年～2026 年上半年的教程/截图描述的是**旧版**。下文严格标注每个事实属于哪个版本阶段。

## 0. 最高优先级结论（给 iOS 复刻团队的 8 条）

1. **历史对话不是独立屏，是左侧滑出抽屉（sidebar / drawer）**，手机首页左上角"三横线"按钮打开。已验证，证据见 §3。
2. **抽屉顶部在 v2.1.0（2026-05-12 灰度）新增"搜索聊天内容"输入框**，抽屉列表按日期分组（截图中可见「今天」）。已验证，证据见 §4。
3. **App 端对话项的操作是"长按"，不是 swipe（左滑）**。长按弹出菜单含 重命名 / 置顶 / 删除；官方 FAQ 明确未提及 swipe 与多选。**(a)** §3.3。
4. **没有多选/批量删除**。官方 FAQ 只写单条删除；批量只有"删除所有对话"（全清）。**(a) + (c)** §3.4。
5. **分享入口在"回复内容"上，不在对话列表上**（App 端）。这是 App 与 Web 的明确差异。**(a)** §6。
6. **当前版本（2.5.1）对话页顶部标题下方不再有模式徽标，输入框下方只剩两个 chip：`深度思考` + `智能搜索`**。**(a)/(b)** §5。
7. **`联网搜索` → `智能搜索` 是文案改名**；`深度思考（R1）` → `深度思考`（R1 字样去掉）。**(a)** §5.2。
8. **导出全部历史对话只有 Web 端**（设置 → 数据管理 → 导出所有历史对话），App 无此入口。**(a)** §7。

**(a) 关键结论**：
- App 端 = **长按（long-press）**触发动作菜单 → 强 iOS 语义的 `contextMenu` 或 `UILongPressGestureRecognizer` + 自定义 action sheet。
- Web 端 = **hover 出现「…」三点菜单** → 两个平台交互模型完全不同，不要照搬。
- 官方 FAQ **从未提到 swipe / 左滑 / 滑动操作（swipe actions）**。

**(b) App 端长按菜单的视觉样式与是否含"分享"**: **未找到截图** → **(c) 未知**。注意：官方 FAQ 只说分享在**回复内容**上长按，**没有**说对话列表项长按菜单里有"分享"（Web 端有）。

**(a) Web 端三点菜单的实际截图**（我已下载核对，《DeepSeek公文写作一本通》图 2-2，`https://book.qq.com/book-read/54834422/10` 配图）：
菜单只有两项：「✏️ **重命名**」「🗑 **删除**」——**Web 端列表项菜单也没有"置顶"**（置顶只在 FAQ 文案里提到，截图版本较旧）。这提醒：**以 FAQ 文字为准，菜单项集合会随版本变化**。

- **(a)** 官方 FAQ 中**不存在**"多选""批量删除""选择多条"的任何条目。中文 FAQ 共 98 个问题标题，我已全量提取，与历史对话相关的只有：重命名、置顶、删除、分享、导出。

### 3.6 对话内容层面的管理

**(a)** 官方 FAQ：
> "检查内容是否位于**对话分支**中：点击对话（提问或回答）**下方的数字箭头**，可切换查看不同分支。"
> —— `#/category/3`「我的对话不见了」

→ 存在 **message branching（重新生成后产生多分支，通过回答下方的数字箭头切换）**。这是复刻时容易漏掉的交互。

**(a)** 每条回复下方的动作区（《DeepSeek公文写作一本通》图 2-1/2-4，Web 端，我已核对截图）：
`复制`（双矩形图标）、`重新生成`（循环箭头图标，hover tooltip 文案为「重新生成」）、`喜欢`（👍）、`不喜欢`（👎）。截图实测这 4 个图标横排、居中、灰色线性。

**(a)** 用户评论指出的限制：**单条消息的"修改/重新生成"次数上限为 6~7 次**（多条评论抱怨"只能改6次"）。这是产品行为，不是 UI 布局，但对复刻的功能边界很重要。

## 14. 给 iOS 团队的复刻基线建议（基于本文已验证事实）

**必须照搬（有强证据）**：
- 顶部导航条：左 hamburger（开抽屉）+ 中标题 + 右 ⊕（新对话），无 Tab Bar
- 抽屉：左侧滑出、右侧 dim、顶部「搜索聊天内容...」、日期分组、当前项浅蓝选中态、可下拉刷新、底部头像行
- 对话项操作：**长按** → 重命名 / 置顶 / 删除
- 输入区：底部大圆角卡片，占位符「发消息或按住说话」，卡片内底行两个 chip（深度思考 / 智能搜索）+ 右 ⊕ + 语音
- 思考过程：进行中「正在思考 ▾」，完成后折叠为「已思考（用时 N 秒） ›」
- 回复动作区：复制 / 重新生成 / 喜欢 / 不喜欢（+分享）
- 消息分支：回答下方数字箭头切换分支
- 全清入口：个人信息菜单「删除所有对话」
- 账号：设置 → 账号管理（换手机号 / 换微信 / 登出所有设备 / 注销）

**建议差异化（官方缺失或做得差）**：
- 单条消息删除（用户明确要求，官方没有）
- 多选批量删除（官方没有）
- 对话项 swipe actions（官方只有长按；iOS 用户对 swipe 的预期更强）
- 在 2.5.1 合并后的极简界面里，把模式切换以"可展开的次要入口"形式保留（大量 1 星差评的核心诉求就是"把专家模式还我"）
