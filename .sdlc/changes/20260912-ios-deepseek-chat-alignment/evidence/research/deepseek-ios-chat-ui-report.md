## 1. 屏幕清单与导航外壳

### 1.1 外壳结论【已验证 + 截图推断】

- **单列导航，无 Tab Bar**。App 没有底部标签栏；所有能力都收在一个会话栈 + 一个覆盖式历史抽屉里。
- **历史对话 = 侧边栏（官方措辞）／覆盖式抽屉**，由左上角 `≡` 唤出。官方 FAQ 逐字：「APP 端：**下拉刷新历史对话侧边栏**，并重新进入目标对话。」
- 会话页顶栏三件套（所有官方截图一致）：**左 `≡`（唤出抽屉） / 中 会话标题（居中）/ 右 `⊕`（新建对话）**。
- 空状态顶栏中央标题为 **「新对话」**（来源：游侠手游 2025-02 安卓实机截图）。

### 1.2 屏幕清单

| # | 屏幕 | 形态 | 入口 |
| --- | --- | --- | --- |
| 1 | 新对话 / 欢迎页 | 单列 | 启动默认；或顶栏 `⊕` |
| 2 | 会话页 | 单列 | 点历史任一行 |
| 3 | 历史对话侧边栏 | **覆盖式抽屉** | 顶栏左 `≡` |
| 4 | 历史搜索 | 抽屉内顶部搜索框（非独立页） | 抽屉顶部「搜索聊天内容」 |

### 1.3 模型 / 功能开关的当前状态（重要，2026 变动剧烈）【已验证】

- 2026-04-08：上线 **快速模式 / 专家模式**（官方描述「擅长复杂问题，高峰需要等待。」）
- 2026-06/07：增加 **识图模式**（release notes 2.2.1「支持识图模式」、2.3.0 再次「支持识图模式」）

### 2.2 布局（自上而下）

1. 顶栏：左 `≡` 圆形浅灰图标按钮 ／ 中央标题 `新对话` ／ 右 `⊕` 圆形浅灰图标按钮
2. **垂直留白**
3. **蓝色虎鲸（orca）图形标记**，水平居中。**注意：品牌图形是虎鲸，不是普通鲸鱼。**

6. 输入卡（见 §5），底部贴近安全区
7. （点 `⊕` 后）输入卡下方出现附件面板：**横滑的最近图片缩略图**（每张右上角有选择圈）+ **三按钮行 `拍照` / `相册` / `文件`**（三按钮为等宽浅灰圆角卡片，图标在上、文字在下）

### 2.3 是否有「建议提示词 chips」

**当前版本（v2.5.x）官方截图里没有任何 suggested prompt chips**——空状态只有「logo + 问候语 + 输入卡」。[截图推断]

R1 时代（2025-02 实机截图）空状态用的是**一段文字**而非 chips：
> `嗨！我是 DeepSeek`
> `我可以帮你搜索、答疑、写作，请把你的任务交给我吧~`

→ 两个时代都没有提示词 chips。**若复刻目标是「像 DeepSeek」，不应加 suggested prompts。**

### 2.4 功能 pill 的形状与两态样式

**形状**：胶囊（full rounded，官方 token `--ds-radius-pill: 100px`）。高度目测约 26–28pt，内含 `图标 + 文字`，图标在左。

**位置**：在**输入卡内部**、位于文本框下方的左下角，两个 pill 横向并排、间距约 8pt。这是 DeepSeek 的显著特征——**功能开关在输入框卡片「里面」，不是卡片外面**。

**两态（从官方截图逐像素采样，us_03 最清晰）**

| 状态 | 底色 | 描边 | 文字 | 图标 |
| --- | --- | --- | --- | --- |
| 未激活 | 白 `#FFFFFF` | 1px 浅灰（实测 `#EDEDED`） | 深色（近 `#0F0F0F`） | 灰色 |
| **激活** | **淡蓝紫 `#EDF3FE`**（官方色阶 deepseek-50，另见 `#D3E2FF`、`#E8EDFF` 家族） | 无描边 | **品牌蓝**（实测 `#426EFE`） | **品牌蓝** |

- pill 左图标：`深度思考` 用「原子/思考」类图标，`智能搜索` 用**地球**图标。
- **默认开合状态【截图推断，中置信】**：2026-09-10 的实拍空态图里，**`智能搜索` 呈激活态（浅蓝底 + 蓝字 + 蓝色地球图标），`深度思考` 为未激活态**。结合桌面版拆解（aiuxplayground, 2026-06-16）的结论 `Search ships on by default in Instant`，推断 **`智能搜索` 默认开启、`深度思考` 默认关闭**。但开关状态会在会话间记忆，因此**不能仅凭一张图定论**，建议真机确认。
- **`⊗` vs `⊕` 的差异【截图推断】**：中文空态截图里输入卡右下显示的是**圆框 ×**，美区同位置是**圆框 ＋**。合理推断：点 `⊕` 展开附件面板后该按钮变为 `×`（关闭面板）。**此点需真机确认。**

## 3. 消息呈现

### 3.1 结论：**用户＝右对齐气泡；助手＝全宽纯文本**（两代一致）

这一范式从 R1 时代延续至今，2026 未改变。

| 维度 | 用户消息 | 助手消息 |
| --- | --- | --- |
| 对齐 | **右对齐气泡** | **全宽、左对齐纯文本** |
| 背景 | **`#EDF3FE`**（淡蓝紫实心） | **无背景**（纯白页面） |
| 描边 | 无 | 无 |
| 文字色 | **`#0F0F0F`** | **`#0F0F0F`**（渲染采样另见 `#18181B`，属抗锯齿） |
| 头像 | **无** | **无** |
| 时间戳 | **无** | **无** |
| 气泡圆角 | **≈12pt 固定圆角（非胶囊）** | — |
| 最大宽度 | **约占屏宽 77%**（实测气泡 789px / 屏宽 1024px） | 内容列宽 ≈ 屏宽（左右各留 ~6% 边距） |

- **`已暂停生成`【评论推断】**：中文评论（v2.4.1）报告「快速模式下，每次 AI 回答完整结束后，末尾会错误显示『已暂停生成』字样」。说明这是**停止生成后的状态标签**，且曾在生成完成时误显示。这同时**反证存在「停止生成」能力**，但**按钮形状/位置/文案【未知】**。

### 8.5 联网搜索的来源 / 引用呈现

**【截图推断 + 已验证（模型侧格式 + 网页端 DOM）】**

- **模型侧引用格式是官方定义的**【已验证，高置信】：DeepSeek 自己的 `search_answer_zh_template` 原文要求按 **`[citation:X]`** 格式在**句末**引用，多个相邻为 `[citation:3][citation:5]`，并明确要求「**切记不要将引用集中在最后返回引用编号，而是在答案对应部分列出**」。检索结果为 `[webpage X begin]…[webpage X end]`。来源：https://github.com/deepseek-ai/DeepSeek-R1/issues/616

- ⚠️ **最大缺口**：**App 答案正文里是否有行内数字 chip、点击行为如何**（触屏无 hover）**完全未知**。官方 5 张截图里答案正文未见行内编号引用，也未见文末来源列表。**请勿假定存在。**

- 旁证：引用**无法在开启搜索时关闭**（官方 issue #1626）。

## 方法学与资源可用性备注

- **唯一拿到高置信度证据的途径**：`https://itunes.apple.com/lookup?id=6737597349&country={us,cn}` 取官方商店截图直链，把缩略图规格段替换为 `1290x2796bb.png` 得原始 PNG，再用图片读取 + PIL 逐像素采样/量距。`web_fetch` 会丢失图片 URL，不适用于此。
- **官方 FAQ 是文案金矿**：`https://static.deepseek.com/faq/index.html?lang=zh`（SPA，需读 JS bundle；可读镜像 `thevibeworks/deepseek-docs`）。分类 1=登录、2=使用引导（历史/设置）、3=对话问题（分支/同步/深色模式异常）、4=API。
- **`aiuxplayground.com/teardowns/deepseek/composer`**：明确标注 `Type: desktop`、`Captured: June 16, 2026`，**描述的是桌面/网页版 composer，不能用于 iOS 消息面**。其 `Instant/Expert` 分段控件在 2026-09 已下线。
- **Mobbin**：有 DeepSeek iOS 条目，但 app 页与 screen 页均被登录墙拦住，图片为加密 URL（未登录无法取用）。PageFlows / UXArchive / Screenlane：未检索到 DeepSeek 条目。
- **知乎 / 少数派 / 人人都是产品经理 / 掘金 / Reddit**：多轮中英文检索均**未命中**可访问的 DeepSeek iOS 消息面拆解。
- **App Store 评论样本 1580 条**（us/cn/gb/ca/au × 10 页，`itunes.apple.com/{cc}/rss/customerreviews/...`），是本报告中所有「行为/缺陷」类结论的主要旁证来源。
- **`chat.deepseek.com` 的 CSS 取不到**（AWS WAF 403 / 挑战页），因此 App 内 Web 聊天与官网的 token 是否完全一致无法直接比对。
- **App Store 版本历史解析陷阱（务必写进团队方法论）**：版本历史每个 `<li>` 内的 DOM 顺序是 **notes → 版本号 → 日期**。按「版本号在前」的直觉解析会得到**整体错位一格**的表，且因为多数日志都是「修复部分已知问题」，**错位后看起来完全合理、极难自查**。正确做法：用 `<li>` 边界成对提取，或交叉校验「同一版本号在页面顶部 What's New 区与列表区文案是否一致」。本报告的版本表已用 `<li>` 成对解析并人工复核。
- **实测取色/量距方法**：iTunes API 的 `screenshotUrls` 把尺寸规格段替换为 `1290x2796bb.png` 得原始 PNG（`1290×2796` = 6.7" @3x 标称尺寸，但该图为**带手机外框的营销合成图**，屏幕区域实测为 x=133–1156，宽 **1024px**）。因此本报告的 px 值均标注为该图坐标；折算 pt 时须以 1024px ≈ 393pt（scale ≈ 2.6 px/pt）为基准，**不要按 1290/430 折算**。
- **营销截图的色彩偏差**：官方截图是 Display P3 / sRGB 转换后的产物，实测品牌蓝为 `#426EFE`，而品牌 token 是 `#4D6BFE`。**不要直接把采样值当规范**，规范值以官方 token 为准。
