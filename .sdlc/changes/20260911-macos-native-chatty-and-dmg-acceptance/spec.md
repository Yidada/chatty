# 具体设计 v1

## 架构
macos/Chatty.xcodeproj + macos/Chatty/ 桌面界面，直接依赖 ../ios/Packages/ChattyKit 的 ChattyCore。使用 SwiftUI + 必要 AppKit 适配，macOS 15 起。暂不移动共享包，避免更改其他客户端的构建路径。生产与 Fixture 为不同 target/bundle，生产包不包含合成登录、测试服务或测试入口。

## 窗口与交互
单个主窗口，默认约 1180×780，最小约 900×620。左侧动态 / Mika / 项目与工作区信息，右侧内容；可收起侧栏。头像打开设置，Cmd+, 可进入设置，Cmd+1/2/3 切换主页面。避免多个窗口同时驱动同一消息队列。切页与设置弹窗保持草稿及已加载状态。

## 功能契约和验收映射
- M1 登录：复用验证码、恢复登录、工作区选择、退出、401 清理。独立 ai.chatty.macos 身份。验证：隔离服务登录/切换/退出，Keychain 和本地数据隔离测试；生产包启动至登录页。
- M2 动态：新进展 / 待处理，所有创作者，独立分页，未读红点；查看只改已读，任务验收采用 expected_revision + suppress_run。验证：他人事项在后一页、已读不移出待办、409 不重复写入。
- M3 Mika：项目选择、连续发送、附件；Cmd+Return 发送，Return 可换行。每次提交快照内容/附件/项目并进入共享 FIFO。验证：延迟回执期间连续 A/B/C 和编辑 D，顺序及项目准确、无重复 POST。
- M4 恢复：后台、退出或冷启动的待发送内容保留但暂停，重新进入由用户继续；未知回执先核对，不自动重发。Mac 失去焦点按已有保守策略暂停，返回时刷新权限。验证：恢复/切工作区/相同文本独立消息测试。
- M5 项目：项目列表、搜索与状态筛选、分页、事项详情、折叠 timeline、进入 Mika 讨论。验证：列表与详情、错误重试、主要动作和深链。
- M6 内容与设置：富文本、代码、链接、任务轨迹、图片与文件预览；NSOpenPanel/文件导入读取用户选中的文件，头像设置内保留现有账号/工作区/运行设备/Agent/Squad 浏览能力。验证：附件合成流程、退出后预览清理、设置返回草稿不丢。
- M7 打包：Release 正常包、应用图标、隐私声明、沙盒最小权限（出站网络、用户所选文件读取），版本化 DMG、校验和、安装说明。验证：签名检查、镜像验证/挂载/复制/启动、架构与 Fixture 隔离检查。

## 安全和兼容性
保持 HTTPS、授权主机检查、API 错误处理与现有生产端点。凭据只入独立 Keychain；不复用浏览器/iOS 凭据。草稿、已读和预览按账号/工作区隔离，macOS 文件增加 owner-only 权限；不将 macOS 原子写入称为 iOS 完整文件保护。用户选择文件只在授权访问期间读取，应用不扫描其它目录。退出停止请求和清理当前客户端数据。外部链接用默认浏览器；内部资源链接仍走授权 API。

## 不包含
APNs、锁屏通知、跨设备已读同步、多窗口队列并发、全局快捷键、自动升级、Mac App Store 上架和自动生产任务写入。多客户端同时改同一会话项目仍受现有后端会话属性限制。
