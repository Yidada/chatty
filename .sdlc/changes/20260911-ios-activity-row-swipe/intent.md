# iOS：动态页逐行滑动操作（左滑 / 右滑）

动态页在 CLE-85 的批量能力之上补齐逐行滑动手势。这是增量：页面定位、两个列表的分页与
已读指纹语义、批量入口都不变，滑动手势只是把同一套动作接到行上。

## 交付行为

- **待处理列表**：左滑（trailing，主操作）「验收完成」→ `done`；右滑（leading，次操作）
  「退回待办」→ `todo`，含从 `blocked` 解锁。
- **新进展列表**：左滑「标记已读」、右滑「标为未读」，只写本机已读指纹，不发任何请求。
- **全滑策略**：只有「标记已读」允许全滑直接执行；`done` / `todo` 必须滑出按钮后点按，
  避免误触改业务状态。
- **颜色**：主操作用强调色，退回 / 撤销类用橙色；两种状态变更都可逆，因此没有红色破坏性样式。
- **滑动阈值与回弹**：全部交给系统 `List` + `.swipeActions`，不自造魔数；滑动行本身不触发导航。
- **选择态**：滑动手势（含 VoiceOver 镜像动作）在选择态下不挂载，退出选择态自动恢复。
- **一套动作定义**：两个列表的动作来自 `ChattyCore.ActivityRowActions`，滑动手势、VoiceOver
  自定义动作、指针右键菜单三处共用同一张表，不是三份逻辑。
- **与批量同源**：状态变更走同一个 `POST /api/issues/batch-update`、同一批次累加器与重试入口；
  `{"updated": N}` 与请求数量不一致即「未生效」，不显示成功，不做乐观更新，提交后从服务端重读。

## 范围与取舍

- 不做服务端新接口、批量审批流、跨工作区操作；不改「动态 = 工作区全量可访问事项」的定位。
- 不扩大到 TestFlight、不做 App Store 提交；版本号与构建号保持不变，本 Issue 不上传。
- 指针菜单保留 CLE-90 的「更改状态」与「复制链接」，并去掉待处理行里与「验收完成」重复的
  「验收通过」；新进展行仍保留「验收通过」，因为该列表的滑动动作是已读对，不构成重复入口。
- 为让 `.swipeActions` 真正生效，列表容器由 `ScrollView` + `LazyVStack` 改为 `List`
  （见 plan.md 的取舍说明）；空态 / 错误提示因此移到 `List` 之外，避免在列表行里塌陷。
