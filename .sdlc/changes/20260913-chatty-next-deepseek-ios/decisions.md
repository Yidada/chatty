# Chatty Next 设计决策

**D22：Chatty Next 默认自动审核，不提供权限模式选择。** 2026-09-13 用户明确要求。Mac 组件审核逐次权限请求；手机确认服务端启用回执后才提交消息。明确授权且低 / 中风险的操作允许一次，危险越权操作拒绝，不确定时人工判断。不修改 Codex 配置或 dsh 全局默认权限。

日期：2026-09-13。D1–D3、D17、D21、D22 来源于用户指令，其余为本轮设计选择。这里记录工程决策，不生成生命周期批准或发布授权。

| ID | 选择 | 理由与代价 |
| --- | --- | --- |
| D1 | iPhone 15 Pro 上全面对齐 DeepSeek iOS，语音为首期核心 | 用户明确选择；未达语音质量不能宣称第一阶段完成 |
| D2 | 请求经 Tailscale 到当前 Mac dsh | 用户明确后端；Mac 服务位置与模型推理位置分别说明 |
| D3 | `Next` 分支，体验完成后讨论开发工作台升级 | 用户明确顺序；不扩大为多机器 / 多 Agent 控制平台 |
| D4 | SwiftUI + 必要 UIKit 原生界面 | 符合现有 iOS 技术基础；WebView 套 dsh 网页会继承桌面结构、键盘与渲染差异 |
| D5 | Native 直连现有 HTTP RPC / WSS | 现有接口覆盖主要通路；代价是准确实现 Cookie、复用流及事件归并。Mac 网关仅在存在实测阻碍时另议 |
| D6 | 独立 bundle / Keychain / 数据目录 | 可与旧 Chatty 并存，减少迁移风险；需要首次重新配置连接，不复用 Multica 账号 |
| D7 | 服务端历史为事实，手机只存草稿 / 待确认发送 / 读位 | 避免两套日志冲突；冷启动离线不能浏览完整服务历史 |
| D8 | 同会话写操作串行，每次用户发送固定 requestId | 防止本地重复点击和快照错配；不能由此承诺跨客户端 exactly-once |
| D9 | 默认不自动重试发送 / cancel | 接受记录不明和 session-scoped cancel 有不同竞态；重连先恢复状态 |
| D10 | 语音先评测设备端 ASR，分段结果用替换归并 | 避免每次音频往返 Mac；硬件 / 语言支持和中文术语效果需实测。达不到预算再比较 Mac 方案 |
| D11（已撤回） | 旧“回填草稿再发送”语音候选失效 | 用户指出与 DeepSeek iOS 交互不一致；不再作为默认流程或实施依据 |
| D12 | 生成中发送先按真实 queue 语义设计候选 | 现有 dsh 可表达；若参考为打断并发送，需服务端原子支持，不能悄悄替代 |
| D13（由 D22 补充） | 需要人工决定时，授权卡提供允许一次 / 拒绝 | 默认先由 Mac 自动审核；卡片仅处理无法自动决定的有效请求 |
| D14 | 渲染组件解除 WorkspaceContext 依赖后复用 | 复用 Markdown / 公式经验；需要旧调用适配与回归，不复制庞大业务模型 |
| D15 | 视觉测量与状态架构分开冻结 | 当前营销图无法证明录音 / 深色 / 动画；阅读原型标为候选，真机截图才作为验收基线 |
| D16 | 只实现已识别且验证过的协议面 | 未知必需事件中止状态推导；需要补采样或适配，避免静默丢字段 |
| D17 | 输入卡片用模型 + workspace 选择替换思考 / 搜索按钮 | 用户在设计页的明确批注；沿用紧凑双入口位置，形成 Chatty 的产品差异；原开关不再计入这两个入口的复刻范围 |
| D18 | 工作目录变更新建会话；模型变更需服务确认后影响后续请求 | cwd 在创建时绑定。保留原历史 / 运行 / 草稿；代价是附件重新上传。模型运行中暂不可切换；selectModel 有共享默认模型副作用，需多客户端验证 |
| D19 | 语音手势与提交步骤以同版本真机记录为准 | 用户要求严格对齐；取证前移除错误演示，不用新的手势猜测覆盖旧猜测 |

| D20 | 语音模式按住录音、松手发送、上滑取消 | DeepSeek 2.4.5 真机主流程已观察；蓝 / 红波形和提示有 USB 录屏。模型 / workspace 保留 D17；精确阈值与边界分支仍待测 |

| D21 | 工具过程默认折叠，连续调用合并为一行 | 用户要求沿用 DeepSeek 默认收起细节的阅读方式。过程入口显示调用次数，点开查看步骤、参数及输出；正文正常呈现，工具授权卡独立显示 |

| D22 | 空文本输入框长按 0.25s 直接开始录音，不切换模式 | 用户明确要求对齐 DeepSeek 的入口。仅空草稿生效，避免抢走文本选择与光标；轻点仍聚焦键盘，松手发送、上滑取消沿用 D20。代价是阈值与结束后模式为候选，需真机对照 |

## 未决与影响

| ID | 未决事实 / 选择 | 解决方式 | 阻塞边界 |
| --- | --- | --- | --- |
| U1 | 实际版本已取得；精确字号 / 显示缩放 / 深色主题 | N0 真机取证 | 像素与系统兼容定稿 |
| U2 | 主流程已取得；取消区移回、已有草稿、短按和系统中断 | 补充 N0 边界取证，主流程已采用 releaseToSend | 语音交互最终冻结 |
| U3 | Apple ASR 中文与术语是否达到 A4 / A5 | N2 成对基准 | 第一阶段语音验收；当前没有成绩 |
| U4 | 生成中发送是否原子打断、参考是否允许排队 | N0 对照 + N1 多客户端测试 | 行为一致性；需要扩展时采用带 expectedTurn 的服务命令 |
| U5 | 删除 / 置顶 / 编辑 / 再生成的能力缺口 | 查实际启用 Remote；没有现成能力则定义最小 dsh 插件契约 | 完整功能对齐；未解决不能删除该验收项 |
| U6 | 运行进程实际协议、Cookie / WSS 与字段兼容 | 原生最小连接切片 | 真实联网验收；磁盘类型和 401 仅提供线索 |
| U7 | 真实模型目录与首个日常 workspace | 由服务目录选择，先用受控目录验证；原型项目名不视为已登记 | 日常本机开发；不猜默认目录就是 Chatty 仓库 |
| U8 | 工具问答的真机往返 | 本轮已读取 user-questions schema 并定义回答策略，配对后采集脱敏交互 | 本机工具闭环不应无提示等待 |
| U9 | 空输入框长按的阈值与结束后是否留在语音模式 | 对照 DeepSeek 2.4.5 真机逐帧观察 | D22 最终冻结；当前实现为候选 |

本轮不需要为可逆设计工件另行确认。未决项按对应检查点取证，只有需要改变用户范围或新增服务依赖时才形成具体选择。
