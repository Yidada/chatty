- 入口：[交互设计阅读页](design.html) · [决策](decisions.md) · [协议](contracts.md) · [对齐矩阵](parity-matrix.md) · [设计证据](design-evidence.md)。

## 1. 设计目标与事实边界

Benjamin 在 iPhone 15 Pro 上通过准确、迅速的语音与文字表达需求，并由自己的 Mac 上的 dsh 接着执行。打开、输入、阅读与切换的体验以 DeepSeek iOS 为参考。

当前核查确认：

- Chatty 的 `AppBootstrap → SessionModel → WorkspaceTabs → ChatModel` 路径绑定 Multica 身份、工作区和 Mika。
- `ChatScreen` 已有历史、富文本、过程、停止、队列及阅读位置处理；这些实现提供复用基础，不能直接称为像素级对齐。
- `RichContentView` 仍接收 `WorkspaceContext`，需要解除链接与附件的业务依赖。
- 本机 dsh 安装包定义了原生接入所需的 RPC / WebSocket，以及会话、文件与工具授权契约。
- 本轮再次从 Mac 探测本地 3080 和 Tailscale HTTPS 8443，均返回 401；没有完成鉴权、没有读取用户会话或发送模型请求。
- 已核对用户 iPhone 15 Pro、iOS 27.0、DeepSeek 2.4.5（build 2），取得语音主流程截图与录屏，见第 4 节及 voice-reference.md；深色和识别性能仍待取证。

## 2. 选定的架构

```text
ChattyNextApp
 ├─ ConnectionModel：首次连接、鉴权与版本错误
 ├─ ConversationModel：当前会话、草稿、发送与阅读状态
 │   ├─ SpeechInputController：录音 → 修订中的文字 → 稳定文字
 │   ├─ DSHClient：HTTP RPC、WSS、上传与来源约束
 │   ├─ SessionReducer：历史事件、临时增量、最终替换
 │   └─ DraftStore：草稿、附件暂存、待核对发送
 └─ ChattyPresentation：消息 / 代码 / 表格 / 公式 / 附件呈现
                         ↓ HTTPS / WSS over Tailscale
                   现有 Mac dsh Web 服务
```

| 边界 | 输入 → 输出 | 不变量 |
| --- | --- | --- |
| UI → ConversationModel | 用户意图 → 状态快照 | View 不拼 dsh 请求；同一会话写操作串行 |
| SpeechInputController | PCM 音频和录音身份 → 分段转写修订 | 旧录音回调不能修改新草稿；最终片段不被后续临时片段覆盖 |
| DSHClient | 固定连接身份、协议命令 → 类型化回执 / 事件 | 不混用两个来源的 cookie；Transport 错误与业务错误区分 |
| SessionReducer | 已验证的事件 / 增量 → 消息与运行状态 | 重复帧不重复显示；丢帧先修复；流结束不自动等于任务成功 |
| DraftStore | 单个会话草稿事务 → 原子存储 | 先落盘，再发请求；无磁盘写成功不能清空唯一一份输入 |
| ChattyPresentation | 纯内容、链接解析策略 → 原生视图 | 不依赖 Multica 登录、Agent、WorkspaceContext；不执行回答中的 HTML / 脚本 |

实施组织：

- 新建 `ios/ChattyNext/`，创建 `ChattyNext` 和独立 fixture scheme，测试 bundle 使用 `ai.chatty.ios.next`。
- 新建 `ios/Packages/ChattyNextKit/`，内含 `DSHTransport`、会话 reducer、发送存储协议和测试。
- 语音采集与 UI 状态放在 iOS 宿主；纯转写分段归并逻辑放入可测试模块。
- 首次可用切片只提取确实共享的富文本依赖。将 `RichContentView` 的链接 / 附件解析改为注入策略；先保留旧 Multica 调用适配，再由 Next 使用新策略。
- 通过 `scripts/generate-ios-project.py` 生成 target，检查当前源码收集规则，防止 Next 文件被旧 target 意外编译。
- 本次不引入通用多后端框架，也不增加常驻 Mac 中间服务。只有明确的 dsh 能力缺口才进入插件扩展设计。

## 3. 用户入口和逐屏状态

### 3.1 首次连接

首次连接属于 Chatty 自己的配置流程。配对完成后，日常打开直接进入最近会话或新对话。

| 状态 | 界面与动作 | 失败处理 |
| --- | --- | --- |
| 未配置 | “连接你的 Mac”；填写 Tailscale HTTPS 地址和当前 dsh 连接凭据；可粘贴完整连接地址 | 本轮原型不接收真实凭据；正式应用在发送前显示目标机器 / 地址 |
| 检查中 | “正在连接…”；防止重复提交 | 连接超时显示“暂时联系不到这台 Mac”，可检查 Tailscale 并重试 |
| 凭据失败 | “连接凭据已失效”；返回配对输入 | 不循环重试 401，不清除对话草稿 |
| 来源不被服务接受 | “服务尚未允许这个连接地址” | 设置页显示可复制的脱敏诊断；不把 403 当成密码错误 |
| 协议不兼容 | “当前服务版本暂不支持此连接” | 保留草稿，停止发送；诊断区记录缺失字段 / 方法 |
| 连接成功 | 加载历史和能力，恢复阅读位置 | 历史加载失败可重试，保留编辑草稿的能力 |

连接地址来源采用本机已有的 8443 Tailscale Serve。TLS 和 Cookie 处理详见 `contracts.md`，不用“网络通了”代替“已登录”。

### 3.2 聊天主界面

| 状态 | 视觉 / 内容 | 可用操作 |
| --- | --- | --- |
| 新对话 | 顶部历史入口与新建；中间 Chatty 标识 / 简短问候；底部输入卡片 | 文字、语音、附件，以及模型 / 工作目录选择。首次发送或文件上传时才创建 dsh 会话 |
| 首次加载 | 在消息区域显示加载反馈，输入框保留 | 草稿编辑；发送等连接与会话恢复完成 |
| 正常历史 | 用户右对齐气泡，助手全宽正文；思考与工具过程默认折叠 | 复制、选择文本、系统分享、代码复制、附件预览 |
| 正在处理 | 已发送内容立即有本地回显；真实 reasoning 与正文增量按类别更新 | 编辑下一条、停止；发送期间按钮语义见 3.5 |
| 已完成 | 最终正文替换同一次回答的临时内容；过程自动收起一次 | 用户手动展开后不被后续刷新再次收起 |
| 离线 / 重连 | 顶部轻量提示“连接已中断，正在恢复…”；已有内容保持可读 | 编辑草稿；不自动提交新的任务 |
| 接受状态不明 | 对应消息标为“正在确认是否已发送” | 查询状态；未确认前不以新 requestId 重发 |
| 回答失败 | 失败说明贴近该次回答，保留已显示文本 | 根据服务事实展示重试路径；不把失败助手消息改成成功 |

### 3.3 历史与会话管理

- 采用左侧覆盖式历史抽屉；现有 `sheet` 无法直接代表侧向抽屉的动画和遮罩，Next 单独实现容器。
- 当前会话高亮，搜索真实服务端内容，返回后恢复本会话草稿和读位。标题、分组和长按菜单的精确排版等待真机。
- 300 ms 搜索防抖为工程初值；请求带本地 `queryGeneration`，迟到的旧查询结果不得覆盖新查询。
- 服务端搜索返回 `hasMore`，但当前声明没有搜索分页游标；有更多结果时提示缩小关键词，不显示无效的“加载更多”。
- 会话 list 的当前返回只有 `items`，不能臆造 `nextCursor`。具体 list 游标语义以协议切片取证补齐。
- 重命名使用 `session/rename` 返回的规范化标题和 `seq`，服务器拒绝时保留原名。
- 删除、置顶、编辑已发送消息、重新生成按对齐矩阵处理。未解决的服务缺口不能用“本机隐藏会话”伪装成服务端删除。
- 录音中切换会话：结束当前采集并把可用转写保留到原会话，随后切换；禁止异步语音写入目标会话。

### 3.4 输入和阅读

- 使用现有 `UITextView` 路线，保留 marked text 检测。中文候选词回车先上屏；常规回车发送 / 换行行为等待真机参考冻结。
- 文字编辑、附件和发送快照分离。发送 A 后输入 B，A 的迟到成功 / 失败不得清空 B。
- 稳定已完成的 Markdown 块缓存；生成中的尾块增量解析，未闭合代码 / 公式先按文本保留，结构完整后替换，避免整段频繁重排。
- 用户向上滚动后停留原位置。新内容显示“回到底部”入口；点击后恢复跟随。
- 读位使用稳定消息身份 + 消息内相对偏移，不依赖数组下标；历史前插、公式高度变化、键盘展开均保留锚点。
- 外部链接走明确的系统打开动作；dsh 工作目录文件按附件接口或后续文件协议访问，不把 Mac 文件路径当成手机 URL。

### 3.5 生成中输入、停止与排队

这是尚缺 DeepSeek 真机操作证据的高影响边界。

- 当前可实施候选：生成中仍可编辑；发送使用 dsh 的 `mode: "queue"`，消息显示“等待回复”，不把排队显示成已开始生成。
- 停止使用 `session/cancel`，只停止当前运行，已排队内容由 dsh 保留。按钮显示“正在停止…”直到权威运行状态更新。
- 禁止自动重试 cancel。它只有 sessionId，迟到的重试可能停止同会话的后续运行。
- 清理队列使用 `session/updateQueue` 的 `remove`，按快照中的具体 itemId 执行，并核对结果。
- 当前 `steer` 表示 dsh 的运行中注入，不等同于 DeepSeek 的“打断并发送”。
- 如果真机证明目标行为是原子打断并发送，现有 `cancel + prompt` 组合存在多客户端竞争。需要 dsh 侧原子接口及 expected-turn 校验；此项属于功能一致性缺口，不能用客户端串行掩盖。

### 3.6 模型与工作目录选择（用户批注修订）

输入卡片底部的两个位置改为“模型 + 工作目录”。这是 Chatty 的明确产品差异，DeepSeek 的思考 / 搜索按钮不再作为这两个位置的复制目标；正文中的真实 reasoning 仍保留。

| 入口 | 展示与操作 | 成功与失败 |
| --- | --- | --- |
| 模型 | 常驻当前模型短名称 + 下拉符号；底部面板显示提供方、模型与选中标记；仅展示实际可路由目录 | 新草稿先保存意向；已有空闲会话等待 selectModel 确认。失败保留旧选择，发送保持关闭直到状态明确 |
| 工作目录 | 常驻目录标题 + 下拉符号；面板同时显示完整 Mac 路径，重名目录可区分 | 新草稿可以直接改选；已有 session 改选后先显示“保留草稿并新建对话”，确认才切到新草稿 |
| 加载 / 无可用项 | 分别显示“正在加载”“暂无可用模型”“暂无工作目录”，失败提供重试 | 不把空列表解释为默认目录；首期选择已登记 workspace，目录登记 / 新建管理暂留 Mac 端 |
| 运行中 / 停止中 / 排队 | 保留当前模型标签，模型切换禁用，直到运行结束、队列为空且发送状态明确 | 工作目录仍可另开对话；明确原任务继续运行，不向原 session 发送 cancel |
| 离线 / 会话恢复中 | 保留最近标签，两个选择暂不可修改，草稿可编辑 | 恢复目录与会话状态后解锁；已删除 / 不可用项必须重新选择，不能静默改到其他目录 |

选择与提交顺序：

1. 新草稿保存 connectionId、模型意向、workspaceId 与用于展示的路径。记忆上次有效选择，无需每次重复选择；首次没有有效目录时要求选定后再发送。
2. 首次发送 / 上传前，校验 workspace/follow 最新目录，并以稳定 sessionId 调用 session/create(workspaceId)。不能同时带 cwd，也不能退回进程默认目录。
3. 创建完成后读取会话事实；应用模型意向，等待 session/selectModel 返回的规范化 selected，再进入上传 / prompt。模型不可用时保留已创建 session 和原草稿，重试不重复建会话。
4. 已有会话的模型变更和后续 prompt 在本客户端串行。服务源码将选择用于 next request，并尝试保存共享默认模型；跨客户端并发下仍无法保证 selectModel + prompt 原子绑定，实测冲突时需要服务端版本校验，不能承诺逐消息锁定。
5. 已有会话更换目录时保留原历史、原运行和原草稿，复制未发送文字及可恢复附件来源到新 draft 身份。文件收据绑定旧 session，不能复制到新发送；新会话需重新上传。原目录不被重命名或移动。
6. 返回历史时从对应 session 的 cwd / model projection 恢复选择。workspace 的分组归属不等于执行目录；目录不匹配时显示实际 cwd，不能伪装成可原地迁移。
7. 模型选择回执丢失时先对账，不把本地勾选当成服务确认。新会话读取当前目录的会话能力，模型不支持现有附件时保留附件并提示处理，不静默删除。

原型面板只使用合成模型和目录，支持选择、关闭、键盘返回、已有会话换目录确认以及草稿示意。未读取真实目录、未建立会话，附件重传和多客户端语义仍待产品实现与实测。

## 4. 语音输入状态机

基线：2026-09-13 在 iPhone 15 Pro、iOS 27.0 上操作已安装 DeepSeek 2.4.5（build 2）。Argent 控制手势，QuickTime 通过 USB 记录中间画面。取证细节见 [voice-reference.md](voice-reference.md)。D11 的旧流程仍然失效，D20 为当前主流程依据。

### 4.1 已观察到的交互

1. 空文字模式的右下角声波按钮切换到语音模式，收起键盘；此点击不开始录音。
2. 语音卡片上部为“按住说话”，下部保持功能入口和键盘切换。Chatty 下部沿用用户指定的模型 + workspace 选择。
3. 持续按住时，底部卡片被蓝色渐变和波形替换，显示“松手发送，上滑取消”。本次记录没有录音中转写文字、计时或独立结束按钮。
4. 正常松手结束采集，并形成发送意图；已观察到识别文字提交后进入回复，无额外转写确认页。
5. 上滑后波形和渐变变红，提示“松手取消”；松手回到原输入界面，没有新消息。
6. 未识别到内容时短暂提示“未识别到内容”，不提交空消息。
7. 键盘图标切回文字模式并展开当前输入法。输入法自身的“点击说话”入口单独归属系统 / 键盘层。

这些观察覆盖空输入的主流程。首次安装默认模式、已有草稿 / 附件、取消区移回、短按阈值、触觉、超时和来电行为仍未取证。原型上滑阈值为画布高度的 10%，取消锁存至松手，属于待标定的保护性候选。

### 4.2 引擎与提交契约

主路线：iOS 26 `SpeechAnalyzer` / `SpeechTranscriber` 候选实现，先评测后冻结。Apple 的接口支持设备端转写及临时结果修订；设备 / locale / 模型资产仍需运行时查询。[官方说明](https://developer.apple.com/videos/play/wwdc2025/277/)

```text
ready(text) ← mode toggle → ready(voice)
                              ↓ hold begins
                           starting → recording
                                         ├─ upward drag → cancelArmed → release → cancelled → ready
                                         ├─ valid release → finalizing(commitIntent)
                                         │                    ├─ nonempty final → send transaction
                                         │                    └─ empty final → empty feedback → ready
                                         └─ system interruption → interrupted → ready
```

`VoiceCommitPolicy = releaseToSend`。最终识别结果与松手可以不同时间到达；只有有效松手产生的发送意图可以消费本次结果。

| 状态 | 输入与输出 | 用户反馈 |
| --- | --- | --- |
| unavailable / needsAssets | 查询设备 / 语言支持和资源 | 可继续文字输入；下载用途和失败可见，不画假录音 |
| needsPermission | 麦克风权限未决定 / 拒绝 | 系统权限或设置入口；授权返回不沿用已松开的按压 |
| starting | 分配 recordingId，冻结会话、连接、草稿修订、模型与目录意向 | 及时反馈；音频实际开始后才视为 recording；精确阈值与触觉待测 |
| recording | 音频 → 带时间区间的临时 / 稳定结果 | 蓝色波形和“松手发送，上滑取消”；产品波形由音量驱动 |
| cancelArmed | 手指进入取消区域 | 红色波形和“松手取消” |
| finalizing | 有效松手停止音频，等待稳定文本 | 不增加确认页；长尾识别反馈的具体视觉需补采，内部状态不等于额外步骤 |
| sending | 非空 final + 有效 commitIntent → 一次本地发送事务 | 回显消息，沿用文本的 accepted / queue / running 状态 |
| empty | 稳定结果为空 | “未识别到内容”；不创建 dsh 会话 / requestId |
| cancelled | 取消使 recordingId 失效 | 丢弃本次识别，恢复原草稿和附件，不发送 |
| interrupted / failed | 来电、后台、失焦、切会话或采集失败 | 撤销发送意图；已稳定文字保留到原会话，提示未完成。此为 Chatty 保护规则，原版仍待对照 |

内部转写记录：`recordingId、rangeStart、rangeEnd、revision、text、isFinal`。同一区间替换修订，按区间拼接，不能重复追加完整结果。

1. 按下冻结原会话、连接代次、草稿快照、插入选区与模型 / workspace；录音中禁止选择器修改。
2. 每个 recordingId 最多消费一次有效 release intent。final 先到时等待松手；松手先到时等待 final；重复事件不重复发起事务。
3. 取消 / 中断先使 recordingId 失效，再停止音频；迟到结果不能发送或修改新的会话。
4. 草稿修订或连接身份发生变化时，保留可用文本到原会话的待处理片段，撤销自动提交。已有草稿如何与语音合并仍待真机取证；当前阅读原型有草稿时保留文字编辑和发送，清空后可切语音。
5. 一旦进入发送事务，分配并持久化稳定 requestId。发送不明时沿用文本对账规则，不能由另一条 ASR 回调重新发起请求。
6. 音频默认仅保留进程内有界缓冲；结束 / 取消释放，不做后台录音。N2 基准样本另存，当前不安装模型或增加云厂商。
7. HTML 只演示合成文字及手势，支持指针按下 / 移动 / 松开、Space 按住 / 松开和 Esc 取消。失焦、pointercancel、切状态均取消。不能用这些检查代替原生识别、触觉、VoiceOver 或速度验收。

## 5. 内容、能力与最小工具反馈

| 内容 | 呈现 | 语义边界 |
| --- | --- | --- |
| text / reasoning | 正文与可折叠思考块 | 只有真实 reasoning 使用“思考”；网络等待 / 工具执行分别标识 |
| tool-call / tool-result | 连续过程合并为一行，默认折叠，显示调用次数；点击展开参数与结果 | 以服务事件关联调用和结果；不把临时工具参数当成执行成功 |
| image / file | 上传状态、预览、错误、移除 | receipt 绑定原 Agent / 会话；不能跨会话重用 |
| approval/request | Mac 默认自动审核，符合任务授权的低 / 中风险操作允许一次；超出授权的危险操作拒绝；不确定或审核不可用时显示确认卡 | 无权限模式选择器；只处理当前有效请求，取消、超时、参数或用户指令变化不能被迟到审核放行 |
| user-questions/request | 对应运行的单选 / 多选 / 文本问题；可展开 detail | 按 question id 返回 selected 标签与 custom；plan-review 的批准项按明确的 approve 标签识别，不能按选项顺序猜测 |
| 未知必需事件 | 显示兼容性错误，保留原始脱敏诊断 | 停止推导业务状态；`ignorable:true` 仅在序列结构验证后可跳过呈现 |

## 6. 本地数据设计

选用带版本的 JSON 原子文件与独立 Keychain。首期暂不需要数据库，也不复制 dsh 的整套日志。

| 数据 | 主键与字段 | 生命周期 |
| --- | --- | --- |
| ConnectionProfile v1 | 本机生成 connectionId；规范化 HTTPS origin；显示名称；schemaVersion | 用户移除连接时清理；origin 改变必须新连接身份 |
| SessionCredential | connectionId + exact origin；cookie 名 / 值 / 过期信息 | Keychain `WhenUnlockedThisDeviceOnly`；不持久保存启动 token |
| ConversationDraft v1 | connectionId + conversationKey；text、revision、attachmentLocalIds、voiceInsertion、modelIntent、workspaceIntent（ID / 标题 / 路径）、updatedAt | 原子文件 / complete protection / 排除备份；移除连接清理 |
| PendingSubmission v1 | requestId；固定 sessionId、workspaceId / cwd、modelIntent / selected、内容快照、附件收据、状态、lastObservedSeq | 接受状态不明时跨重启保留；收到持久回显后退休 |
| ConnectionPreferences v1 | connectionId；上次有效 modelIntent / workspaceId | 仅用于新草稿；重连校验，不能覆盖已有会话事实 |
| ReadingAnchor v1 | connectionId + sessionId；stableMessageId、relativeOffset、followingBottom | 当前会话关闭时保存；锚点失效时退回最近已知消息 |
| Message cache | 当前打开的历史窗口与临时流 | 首期只保存在内存；重启后离线可恢复草稿，不承诺离线完整历史 |
| Attachment staging | 随机本地 ID、文件类型 / 大小 / 路径、原会话身份、上传状态 | 未发送附件随草稿保留；临时下载按使用结束或过期清理 |

硬约束：

- Connection 不用 origin 的文本前缀比较；URL 规范化后精确比较 scheme / hostname / effective port。
- 新对话使用 `draft:<UUID>`；首次创建使用稳定的客户端 sessionId，成功后原子迁移草稿键。创建失败不得无边界地产生多个会话。
- 空间不足 / 文件保护不可用时停止发送并保留 UI 文本，不能先清空后报告存储失败。
- 退出 Next 不删除 dsh 服务端历史。卸载或回退也不能撤销已执行的本机操作。
- 不迁移 Multica token、Mika 会话、任务 ID 或旧 outbox 到 dsh。

## 7. 视觉、无障碍与实测参数

首批视觉参数为候选。精确数值必须由 iPhone 15 Pro 真机截图与录屏标定。

| 项目 | 候选 / 规则 | 证据状态 |
| --- | --- | --- |
| 浅色背景 / 品牌强调 | 沿用候选白底与 `#4D6BFE` | 当前 `Theme.swift`；待真机色彩空间对照 |
| 用户气泡 | 候选 `#EDF3FE`，右对齐 | 已有主题与营销素材 |
| 助手正文 | 全宽无外层气泡，逐块排版 | 现有素材支持方向；精确字号 / 行高待测 |
| 历史抽屉 | 左侧覆盖、背景遮罩、关闭后焦点返回入口 | 具体宽度、阻尼、手势阈值待测 |
| 语音面板 | 输入区替换为录音状态，取消反馈清晰 | 蓝 / 红波形与提示来自 2.4.5 真机；精确尺寸与阈值待测 |
| 深色 | 阅读原型仅使用候选色 | 未取得真实 DeepSeek 深色参考，不可作为通过基线 |

- 默认字号截图用于像素比较；Dynamic Type 下布局可扩展，不能截断按钮或隐藏正文。
- 隐形点击区域至少 44 pt，视觉图标按参考尺寸呈现。
- VoiceOver 标签区分“开始录音”“停止录音”“停止当前回复”；增加可替代长按 / 滑动的动作。
- 屏幕阅读器不逐 token 播报长回复；只播报阶段变化和完成提示，正文由用户阅读。
- Reduce Motion 下减少位移 / 弹簧，使用低强度过渡；不以动画完成回调作为业务事件。
- VoiceOver 对话抽屉与确认卡焦点隔离；关闭后回到原按钮或输入区。
- 触摸、语音和渲染延迟用同一设备的单调时钟测量；跨 Mac / iPhone 时钟不直接相减。

## 8. 兼容、落地顺序与回退

1. 保持 main 产品和旧方案证据；Next 新建独立 bundle、Keychain service 和存储根。
2. 先锁定协议清单及合成契约样本，完成直连、身份和事件归并的最小切片。
3. 引入真实语音切片并评测，再逐屏对照。
4. 共享渲染组件提取时，用注入适配保持旧调用行为；通过旧核心测试和相关 Apple 构建后继续。
5. 本地 schemaVersion 变化采用“新文件写入 → 验证 → 原子替换”，保留可恢复旧版本；遇到较新 schema 时只读提示，不覆盖。
6. dsh 协议采用“已验证适配版本 + required shape 检查”，不以 launcher 版本推断运行协议；未知非可忽略数据停止发送 / 状态推进并提示兼容错误。
7. 回退到旧 Chatty 安装包 / main 时不会读取 Next 数据；Next 服务端会话仍在 dsh。服务端任何未来删除或执行副作用无法靠 Git 回退恢复。
8. 当前设计不升级 dsh、不修改 Tailscale、不配置全局授权，也不发布安装包。
