# Chatty Next 实施计划

状态：规划草案。用户已明确产品方向、分支与目标设备；以下技术拆分和数值预算为工程建议，均待实际验证。

设计已细化：[交互阅读页](design.html)、[设计规范](spec.md)、[协议契约](contracts.md)、[决策与未决项](decisions.md)。具体实现遵循设计中的接口与兼容边界；本计划继续定义范围和验收目标。

## 1. 最小有用交付

在 iPhone 15 Pro 安装独立的 Chatty Next 测试应用，完成一次“语音输入 → 准确文字 → Tailscale → 本机 dsh → 真实增量回复 → 停止 / 恢复历史”的完整对话。

这一交付用于尽早验证最难的两项：语音质量和真实连接。第一阶段最终完成，还必须通过后面的逐屏对照与日常使用验收。

## 2. 先解决三个约束冲突

| 冲突 | 处理 |
| --- | --- |
| 全面对齐 DeepSeek 与旧三 Tab 工作台入口不一致 | Next 采用聊天首页与历史抽屉；机器连接放在一次配置与设置中，日常输入无需选择 Agent / Runtime |
| “又快又准的语音”无法由 dsh 接入自动获得 | 独立验证 ASR；先测 iPhone 端识别，未达标时比较 Mac 侧识别方案，不用假转写填充演示 |
| 视觉完全一致与不同后端能力存在差距 | 建立逐项能力矩阵；模型 / 工作目录选择、重试、编辑、删除等必须有真实语义；两个原开关按用户批注替换。缺口需补齐或得到明确范围取舍，未解决时不宣称完整对齐 |

## 3. 原生界面与连接结构

建议的数据流：

```text
iPhone 15 Pro
  麦克风 → ASR → 输入框文字
  输入 / 会话 / 消息 / 附件
          ↓
  DSH 客户端（鉴权、请求、事件、重连）
          ↓ HTTPS / WSS，走 Tailscale
  Mac 的 Tailscale Serve
          ↓ loopback
  当前 dsh web 服务 → Session / Agent / 本机工具 / 当前配置的模型
```

- 默认复用现有 dsh Web 接口，先以原生客户端直接接入验证可行性。
- 已安装接口定义使用 HTTP RPC 与 `/api/remote.mux` WebSocket。不能假设它提供 OpenAI chat-completions 或 SSE。
- 已安装文档要求在目标 host + port 上交换启动凭据，取得 cookie；不能直接套用 Chatty 现有 Bearer 登录。
- 配对凭据与 cookie 使用受保护存储，只发送给固定 HTTPS 来源；dsh 的模型密钥留在机器上。
- dsh 会话和持久事件是历史与执行事实来源；手机保存会话草稿、读取位置、临时增量和待核对发送状态。
- `requestId`、会话 ID、持久事件序号、流中的临时片段必须分别建模。最终持久消息到达时替换临时内容，避免重复一份回答。
- 断线后先恢复历史和运行状态，再接续输出。连接中断不能自动解释为任务停止，也不能自动重发一条新任务。
- 只有直接接入无法满足协议或寿命管理时，才增加最小 Mac 适配服务；决定前提供失败证据和接口范围。
- “本机 dsh”说明执行服务的位置。模型推理仍取决于 dsh 当前配置，不能据此宣称离线或全部本地推理。

## 4. 语音路线

默认先评测 iOS 26 的 `SpeechAnalyzer` / `SpeechTranscriber`。Apple 提供设备端转写和临时 / 最终结果；实际设备、语言及模型资产支持需运行时确认。[Apple 官方说明](https://developer.apple.com/videos/play/wwdc2025/277/)

1. 在同一台 iPhone 15 Pro 对 DeepSeek 和候选方案做成对测试，记录设备、系统、语言、网络、环境与模型冷暖状态。
2. 样本至少 30 条：10 条自然中文，10 条含 Chatty / DeepSeek / Tailscale / Git 等术语的中英混合表达，10 条较长或带环境噪声的表达。
3. 同一条话语重复回放给两套方案，并保留一轮本人自然口述，避免扬声器回放代表全部体验。
4. 分开测“按下后进入录音”“停止说话后文字稳定”“识别错误”“需要手动修改的比例”。如果参考 App 不显示实时转写，也不能用后台转写事件代替用户可感知延迟。
5. UI 按真机参考定义按住、点击、松手、上滑取消、编辑和发送行为；未知行为先记录，不能从营销截图推导。
6. 设备端识别未达标时，再比较经 Tailscale 到 Mac 的识别方案。选型报告必须覆盖中文和术语准确率、首用下载、处理延迟与失败恢复。
7. 麦克风拒绝、电话打断、无声、识别失败、模型未安装都需有具体反馈；失败不触发 dsh 请求，既有草稿保持可编辑。

ASR 只负责产出文字。聊天请求始终进入当前 Mac 的 dsh。语音质量未达标时，第一阶段保持未完成。

## 7. 验收清单

以下数值是**初始工程预算，尚无测试结果**。N0 测量 DeepSeek 后记录最终预算与依据；任何放宽都要显示在差异清单中，不能用宽松预算掩盖可感知退步。

| 编号 | 可观察结果 | 具体检查 |
| --- | --- | --- |
| A1 首屏与导航 | 配对后打开即聊天，历史与新建位置 / 手势对齐 | 同设备、同设置逐步录屏；包含冷启动、空历史、有历史和返回原会话 |
| A2 视觉 | 状态相同的截图可对照叠加 | 固定内容、语言、字号、主题和键盘；测字号、基线、边距、圆角及颜色。关键几何误差目标 ≤ 1 pt；颜色在统一色彩空间比较。只屏蔽状态栏时间和标记的品牌区域 |
| A3 动画与触感 | 输入、抽屉、键盘、录音和自动折叠反应自然 | 同机同刷新设置录屏 / 手动触感对照。触摸反馈 p95 ≤ 100 ms，关键动画时长与参考差异目标 ≤ 10%；统计掉帧并与参考比较 |
| A4 语音速度 | 开始录音立即有反馈，结束后迅速得到稳定文字 | 30 条成对样本及独立冷启动样本。暖态录音反馈 p95 ≤ 100 ms；语音结束至稳定文字 p95 目标 ≤ 1 s，且比 DeepSeek 增加不超过 200 ms。冷启动单列，不混入暖态 |
| A5 语音准确 | 常用中文与中英术语少改字即可发送 | 普通中文规范化字符错误率目标 ≤ 3%，混合 / 噪声组 ≤ 5%；预先标注术语准确率 ≥ 95%。各组相对 DeepSeek 的字符错误率增加 ≤ 1 个百分点；保留原始与规范化文本以及人工修改比例 |
| A6 真实连接 | 同一请求可在当前 Mac 的 dsh 会话核对 | 从 iPhone 的蜂窝网络 + Tailscale 发请求，关联 `requestId` / 会话 ID / 最终事件；用受控目录的唯一标记读取证明确为该机器执行 |
| A7 真实流式与阅读 | 正文增量出现、停止有效、历史无重复，读旧内容不被拉走 | 固定增量流验证顺序与最终替换；真实 dsh 验证事件到屏幕 p95 目标 ≤ 100 ms。分别记录网络、模型首字和 UI 延迟，不以打字动画模拟完整回复 |
| A8 会话连续性 | 新建、搜索、切换、重命名等参考操作真实成立 | 每次动作核对服务端与重新打开结果；草稿和读位按会话恢复。删除 / 编辑 / 重新生成等能力缺口逐项补齐或明确取舍 |
| A9 内容与附件 | 中英文、代码、表格、公式、图片及文件状态正确 | 固定富文本样本与真实上传分别验证；相机、相册、文件和消息菜单逐项对照。后端不支持的能力不能用可点击空壳交付 |
| A10 失败恢复 | 网络、鉴权、麦克风、后台和停止失败可理解且不丢内容 | 断 Tailscale、Wi-Fi / 蜂窝切换、401、dsh 重启、拒绝麦克风、电话打断、切后台。恢复先核对状态；凭据失效提示重新连接；操作回执未确认时不显示成功 |
| A11 本机工具 | 普通对话和需要本机工具的请求都能结束 | 最小只读目录任务可核对结果；工具需要授权时显示等待及原有允许 / 拒绝结果；不静默放行、不把工具运行统称模型思考 |
| A12 日常体验 | 核心流程没有明显退步 | 用户在 iPhone 15 Pro 完成不少于 10 轮文字 / 语音混合对话，切换 3 个历史、停止 1 次、恢复 1 次网络；记录主观差异和对应录屏 |
| A13 模型与工作目录 | 输入卡片可选择实际模型与 workspace，当前选择始终清楚 | 选择回执、不可用项、运行中、离线、换目录新会话与草稿复制；原会话 / 运行保留，附件收据隔离；多客户端冲突单独验证 |

## 8. 测试与证据安排

- Swift 层：鉴权来源隔离、事件增量转最终、游标补齐、重复帧、请求幂等、取消失败、会话草稿以及语音状态切换。
- 原生交互：欢迎 → 录音 → 文字 → 发送 → 阅读 → 停止 → 历史 → 回到草稿；中文输入法、键盘变化、长回复、权限与后台中断。
- 真机联网：至少分别记录局域网和蜂窝 + Tailscale 两条通路；只有 Mac 上的 HTTP 探测不能满足这一项。
- 构建时保留现有核心测试命令：`swift test --package-path ios/Packages/ChattyKit --scratch-path .tools/ios-swift-build`。新包创建后增加对应包测试和 `ChattyNext` 宿主 XCTest。
- 设备任务串行执行。截图比较使用固定内容；语音和真实服务单独计时，合成服务通过不能代替这两项。
- 每个检查点记录版本 / commit、设备 / 系统、输入、期望、实测、失败和残留差异。本轮只有规划与只读核查，不运行产品测试来制造通过记录。
