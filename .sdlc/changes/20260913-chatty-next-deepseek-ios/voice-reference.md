# DeepSeek iOS 语音真机观察

状态：空输入主流程已取证，HTML 原型已重做；像素、边界手势与语音质量未验收。

## 基线与方法

- 2026-09-13，iPhone 15 Pro，iOS 27.0（24A435），已安装 `com.deepseek.chat` 2.4.5（build 2）。
- 界面为简体中文、浅色。系统字号 / 显示缩放未读取，不推定为默认。
- 按用户提供的 [Software Mansion 发布帖](https://x.com/swmansion/status/2096974561971523981)采用 Argent 0.25.0 USB。官方能力见 [实体 iOS 说明](https://docs.swmansion.com/argent/docs/features/physical-ios-devices/)。
- 用户开启开发者模式后，CoreDevice 显示 enabled。使用既有团队证书，为该手机创建专用开发描述文件并安装 ArgentRunner，真实控件树与手势已成功。
- Argent 的截图会排在长按结束后，无法独立捕获中间状态。使用 QuickTime 的 iPhone USB 屏幕源取得 43.843 秒连续录屏，无音轨；原文件留在忽略目录 `.tools/argent-voice-reference/`。
- 原始截图与录屏尺寸分别为 1178×2556 和 1180×2556；不把采集编码宽度差当成 UI 尺寸差。录屏中的 9:41 属于采集画面，不能用于推算操作时刻。

## 应用到 Chatty 的设计

1. 采用上述模式切换、按住、正常松手发送、上滑取消和空结果反馈；移除旧的结束按钮 / 转写确认页。
2. 下方两个功能位按用户要求保留模型和 workspace；录音时暂时隐藏并冻结其选择。
3. 正常松手只创建一次提交意图。最终识别结果准备好后进入现有 dsh 文本事务，不增加语音 RPC。
4. 取消、中断和迟到结果按 recordingId 隔离，原草稿和附件不能写入另一个会话。
5. HTML 使用固定合成文字，不采音、不请求 dsh。键盘 Space / Esc 和意外失焦取消用于可访问操作和保护，尚未对应原版 VoiceOver 行为。

## 仍需补采

- 已有草稿 / 附件时的入口、组合和取消后恢复。
- 取消区移入后再移回、最短按住时间、超长录音、权限拒绝、来电与后台。
- 录音启动、最后文本稳定、发送回显的分离计时；中文与开发术语的 30 条成对基准。
- 深色、字号、显示缩放、精准位置 / 动画和触觉。当前蓝 / 红渐变可用于视觉方向，尚未达到像素验收。

Argent 真机自定义手势不能任意多段往返，因此未伪造取消后移回的对齐结果。HTML 当前将取消锁存到松手；上滑阈值为画布高度的 10%，均明确标为候选。
