# Pixel 日常操作流畅性规格

2026-09-09；设计草案。关联 CLE-70 / CLE-73，承接 intent.md §15 的 1A–6A。

## 用户问题与最小交付

用户 在 Pixel 上使用对话、项目、设置时，感觉等待、重复操作和卡顿过多。
首个交付是一次可复现的体验诊断：记录操作路径、等待时长、重复请求、发送不可用区间和帧表现，选出一个影响最大的瓶颈。缓存是候选解决方式，诊断可以支持更小的修复。

## 路径与验收检查

| ID | 可观察结果 | 具体检查与证据 |
|---|---|---|
| UX1 | 启动后能看到内容，并明确何时可以输入/发送 | 分别记录首屏、消息可见、编辑器可用、权限确认完成；冷/热启动分别采样，禁止用首屏替代可操作时间 |
| UX2 | 对话→项目→详情→返回→对话保留位置与草稿 | 固定重复路径，比较滚动位置、筛选、详情与草稿；记录重载次数、空白/阻塞区间和点击次数 |
| UX3 | 普通内容刷新避免不必要的操作中断 | 慢响应 fixture 中记录 capabilitiesCurrent、sending、loading 与按钮状态；分别模拟内容更新、权限失效和 Runtime 变化 |
| UX4 | 重复访问可尽快展示已有内容 | 同一账号/工作区二次访问与进程恢复分开测量；标注缓存时间，统计命中、请求数量、字节数与前台就绪时间 |
| UX5 | 长对话和实时内容更新时保持滚动稳定 | S2 分页到目标窗口、注入实时事件，记录帧 overrun、CPU、位置跳动、消息重复/缺失；现有仅首窗口滚动测试不足 |
| UX6 | 弱网与断网仍有清晰反馈和恢复行为 | 延迟/429/503/WS 断连/进程重启；已有内容与草稿可见，禁止离线自动发送和失败写请求自动重放 |
| UX7 | 缓存不跨身份泄漏，权限限制可靠 | 账号/工作区切换、登出、401、资源403、权限撤销、Runtime 重绑；核验读取/清理范围与发送拒绝 |

上述为功能验收方向。毫秒、P95、请求数与内存预算 T 仍待同条件 B0 实测与验收；本文件不宣称现状达标。

## 拟定行为与失败恢复

- 内容刷新与身份/权限检查分开建模。内容刷新保留已有列表与输入草稿。发送是否允许必须由有效权限状态决定，不能只删除 canSend 检查。
- 缓存按服务地址、账号、工作区与资源身份隔离；采用已批准的私有存储、禁备份、离线只读和容量方向，详见 intent.md §15。
- 401 使会话失效；403 清理/隐藏对应资源，不自动删除有效凭据。身份尚未确认时不能展示上个账号的缓存。
- 空列表必须区分成功空响应、加载中和请求失败。失败刷新不能伪装成成功空数据。
- 草稿允许本地保留；发送回执未知时保留未知状态，禁止自动重发。
- 新缓存应带版本与失效规则；损坏或不兼容时丢弃可再获取的业务缓存并重新读取，凭据和草稿单独处理。

## 边界

本轮 Android/Pixel 优先。iOS、服务端协议修改、APNs、离线写队列和真实账号自动发送不在当前实现范围。数据库选型、权限新鲜度策略和调度策略需诊断后补充具体设计，不能凭此草案直接进入缓存产品实现。
